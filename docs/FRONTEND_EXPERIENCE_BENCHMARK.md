# Frontend Experience Benchmark — 前端体验基准测试

> 交互逻辑与前端美感测试体系。不只问"好不好看"，而是测试：
> 1. 用户是否知道自己在哪里
> 2. 用户是否知道下一步做什么
> 3. 页面是否像同一个产品
> 4. 动效是否自然
> 5. 交互是否像"靠近牌面"，而不是"操作后台"
> 6. 明暗主题是否对称
> 7. 女性友好是否真实成立
> 8. 页面是否有电子屏幕的活性，而不是纸质说明书

## A. 信息架构与用户路径（15 分）

### A1. 首页入口是否清楚（3 分）

**测试问题：**
- 用户是否一眼知道有三种进入方式？
- 今日一牌 / 问题解读 / 深度牌阵边界是否清晰？
- 是否默认推荐问题解读？
- 用户不知道选哪个时是否有提示？

**通过标准：**
- 用户 5 秒内能说出三种模式的区别
- "问题解读"有推荐标记
- 有辅助提示："不知道选哪个？从「问题解读」开始就好。"

**失败表现：**
- 三个入口像三个差不多的卡片
- 用户不知道该选哪个
- "深度牌阵"看起来像高级付费按钮

### A2. 问题解读流程是否自然（3 分）

**必须是：**
```
输入问题 → 系统复述 → 用户确认/修改/保留 → 推荐牌阵 → 抽牌 → 牌面先出现 → AI 解读生成 → 笔记/退出/继续看
```

**失败表现：**
- 输入问题后直接抽牌
- 系统复述后不给修改权
- 抽牌和 AI loading 混在一起
- 结束页只剩重抽和分享

### A3. 档案库是否像"探索牌面"（3 分）

**通过标准：**
- 用户感觉是在触摸/探索牌面，而不是点目录
- 牌面是中心，符号点是入口，解释从牌面附近浮现

**失败表现：**
- 左侧目录 + 中间图片 + 右侧说明
- 像文档页、说明书、后台详情页

### A4. 笔记系统是否有长期价值（3 分）

**通过标准：**
- 用户不仅能在解读结束写一句话
- 还可以平时打开笔记继续补写、回看、固定快照

**失败表现：**
- 笔记只是结束页一个 textarea
- 刷新后丢失
- 没有快照、没有回看、没有补写时间线

### A5. 视频演示入口是否预留（3 分）

**通过标准：**
- ReadingScript 能同时服务网页解读和演示模式
- 至少有 9:16 预览结构

**失败表现：**
- 网页解读和视频脚本完全分裂
- Remotion 目录空着

## B. 交互逻辑与状态一致性（15 分）

### B1. Loading 文案准确（3 分）

**必须区分：**
- 正在抽取牌面……
- 牌面已出现
- 正在读取牌面符号……
- 正在整理解读……

**严重失败：** 实际在等 AI，却一直显示"正在抽取牌面"

### B2. 抽牌与 AI 解读分离（3 分）

**通过标准：**
- 抽牌本地 300ms 内完成
- 动画 1.2-1.8s
- 牌面先出现
- AI 后台生成
- AI 失败不丢牌面

### B3. 状态机完整（3 分）

**必须有：**
idle → mode_selected → question_input → question_reframing → question_confirmed → spread_recommending → spread_selected → shuffling → card_revealed → generating_reading → reading_ready → reflection_note → completed → error

### B4. 用户有修改权和退出权（3 分）

**必须存在：**
- 我想改一下
- 保留原问题
- 这段解读不太像我
- 到这里就好
- 暂时不保存

### B5. 交互不是命令式（3 分）

**通过标准：**
- hover 像靠近
- click 像选择
- 解释像浮现
- 牌面像响应

## C. 视觉系统与美感一致性（20 分）

### C1. 明暗主题是否对称（4 分）

**测试问题：**
- 浅色和暗色是否像同一个产品？
- 是否只是光照不同，而不是两个世界？

**通过标准：**
- 浅色 = 月白档案馆
- 暗色 = 夜色档案馆
- 同一套 token，同一套材质，同一套卡片结构

**失败：** 浅色像纸张手账，暗色像黑色 SaaS

### C2. 字体系统统一（4 分）

**规则：**
- 中文标题：LXGW WenKai
- 正文 / UI：PingFang SC / Noto Sans SC
- 英文 / 编号：Inter

### C3. 卡片、按钮、标签是否同一语言（4 分）

**检查：** mode card / archive popover / reading card / note card / keyword chip / button

**通过标准：** 它们都像来自"阈牌档案馆"

### C4. 牌面是否是视觉中心（4 分）

**通过标准：**
- 牌面是主角
- UI 是围绕牌面长出来的
- 解释不抢牌面

### C5. 微光、流沙、烫金是否克制（4 分）

**通过标准：**
- 用户能感觉页面有生命感，但不会觉得是特效
- 光标靠近时有一点光
- 烫金只用于 accent
- 流沙不影响阅读

## D. 动效与交互手感（15 分）

### D1. 页面切换是否连续（3 分）

**通过标准：** fade + slight blur + y offset，没有硬切

### D2. 缩放是否自然（3 分）

**通过标准：** transform scale + spring/easeSoft，不动画 width/height

### D3. 牌面 reveal 是否有纸牌物理感（3 分）

**通过标准：** 牌背出现 → 抽出 → 翻开 → 落下 → 阴影稳定 → 牌名淡入

### D4. Hotspot 是否像"靠近符号"（3 分）

**通过标准：** stagger 出现 → hover 点亮 → 解释浮现 → 线条像手写

### D5. Reduced Motion 是否支持（3 分）

**必须有：** @media (prefers-reduced-motion: reduce) 关闭复杂动效

## E. 女性友好与情绪安全（15 分）

### E1. 感情问题是否安全（3 分）

**输入测试：** "他会不会回来？" / "他到底喜不喜欢我？"

**通过标准：** 不能替对方下定论，必须回到用户感受

### E2. 是否不制造焦虑（3 分）

**检查：** 不神准、不倒计时、不恐吓、不鼓励重抽、不说命中注定

### E3. 用户是否有不接受权（3 分）

**必须有：** 这段解读不太像我 / 保留原问题 / 我想自己改 / 到这里就好

### E4. 是否允许模糊和慢（3 分）

**文案要允许：** 不需要完整、不需要正确、可以慢慢写、可以先停下

### E5. 笔记是否温柔而非打卡（3 分）

**通过标准：** 笔记是回看空间，不是打卡压力

## F. 响应式与可访问性（10 分）

### F1. 移动端可用（2 分）— 测试 390px / 768px / 1440px
### F2. 对比度（2 分）— 主文字清晰，辅助文字不消失
### F3. 键盘可访问（2 分）— Tab 遍历，focus ring 可见
### F4. ARIA 与语义（2 分）— hotspot 有 aria-label
### F5. 图片加载与尺寸（2 分）— 有 width/height，无 layout shift

---

## G. 产品差异化与记忆点（10 分）

### G1. 是否区别于普通塔罗 App（2 分）
### G2. 是否有"活牌面"体验（2 分）
### G3. 是否有长期使用价值（2 分）
### G4. 是否适合自媒体演示（2 分）
### G5. 是否有统一气质（2 分）

**一句话描述：** 神秘，但不廉价；温柔，但不操控；可交互，但不命令化；像电子屏幕上的活牌面。
