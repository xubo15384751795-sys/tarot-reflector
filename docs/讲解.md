# 阈牌参考样本 — 讲解文档

> 本文档面向**接手评估或继续开发**的开发者。  
> 项目定位：**参考样本 v0.1**，不是完整产品。

---

## 1. 这个样本解决什么问题

用最小可运行代码，演示一条完整用户路径：

```
提问 → 选领域 → 洗牌动画 → 翻牌 → 分步解读（牌面标注 + 文字）
```

你可以：

- **只跑起来看效果** — 给产品/设计评估交互
- **只复用 UI** — 换掉解读逻辑
- **在此基础上接 AI** — 接口和扩展点已预留

## 4. 核心数据类型（`src/lib/schema.ts`）

接手者最需要熟悉这三个类型：

### UserInput — 用户输入

```typescript
{
  question: string;      // 必填
  domain: Domain;        // love | career | study | project | money | self
  context?: string;      // 可选补充背景（已预留，模板引擎暂未用）
}
```

### TarotReading — API 返回 / 前端消费

```typescript
{
  title: string;
  thesis: string;        // 一句话核心洞察
  card_id: string;
  card_name: string;
  zh_name: string;
  orientation: "upright" | "reversed";
  domain: string;
  motifs: Motif[];       // 牌面元素 + 标注坐标
  image: string;         // 如 /cards/major/16_the_tower.jpg
  scenes: TarotScene[];  // 分步解读
  closing_line: string;
  disclaimer: string;
}
```

### TarotScene — 解读页每一步

```typescript
{
  scene_id: number;
  type: "opening" | "motif_focus" | "mapping" | "closing" | ...;
  step_label: string;    // 进度条显示：整体 / 元素一 / …
  headline: string;
  subtitle?: string;
  insight?: string;
  body: string;
  connection?: string;   // 与用户问题的关联提问
  focus_motif?: string | null;  // 对应 motifs[].id，驱动牌面高亮
  duration: number;
  ...
}
```

## 5. HTTP 接口

### GET `/api/reading`

返回 JSON 格式的**接口说明**（契约、环境变量、已注册引擎）。  
浏览器或 curl 可直接访问，方便接手者快速了解。

```bash
curl http://localhost:3000/api/reading
```

### POST `/api/reading`

**请求体：**

```json
{
  "question": "该不该接受这份 offer？",
  "domain": "career",
  "context": "目前在职三个月，新 offer 薪资高 20%"
}
```

**成功响应：** `TarotReading` 对象（200）

**错误：**

| 状态码 | 含义 |
|--------|------|
| 400 | 未提供 question |
| 500 | 生成失败 |

## 6. 扩展接口（继续开发时改这里）

所有扩展点集中在 `src/lib/reading/`。

### 6.1 ReadingGenerator — 解读引擎

```typescript
interface ReadingGenerator {
  readonly id: string;       // "template" | "ai"
  readonly label: string;
  generate(ctx: ReadingContext): Promise<TarotReading>;
}
```

| 文件 | 状态 | 说明 |
|------|------|------|
| `templateGenerator.ts` | ✅ 已实现 | 本地模板，默认引擎 |
| `aiGenerator.stub.ts` | 📝 骨架 | 待填 `callLLM()` |

**切换引擎：** 在 `.env.local` 设置

```env
READING_PROVIDER=template   # 或 ai
```

注册表在 `reading/index.ts` 的 `GENERATORS` 对象；新增引擎时加一项即可。

### 6.2 CardDrawer — 抽牌策略

```typescript
interface CardDrawer {
  draw(domain: Domain): CardDrawResult;
}
```

默认：`drawCard.ts` 随机大阿卡纳 + 随机正逆位。

若要做「同一用户不重复抽牌」「按领域加权」，实现新 `CardDrawer` 并传入：

```typescript
generateReading(input, { cardDrawer: myDrawer });
```

### 6.3 接 AI 的推荐步骤

1. 复制 `.env.example` → `.env.local`，填入 `LLM_API_KEY`
2. 设置 `READING_PROVIDER=ai`
3. 编辑 `aiGenerator.stub.ts` 中的 `callLLM()`：
   - 调用 OpenAI 兼容 API
   - prompt 用 `buildDynamicReadingPrompt(ctx)`（已读 `prompts/dynamic_reading_prompt.txt`）
   - 解析 JSON 为 `LLMReadingPayload`
4. `mergeReadingFromLLM()` 自动补全牌面字段（image、motifs 等）
5. `validateReading()` 校验结构后再返回

**回退策略（已实现）：** 无 API Key 或 AI 失败时，自动回退模板引擎。

### 6.4 其他预留

| 位置 | 用途 |
|------|------|
| `UserInput.context` | 补充背景，prompt 已支持 `{{context}}` |
| `prompts/dynamic_reading_prompt.txt` | AI 系统提示词模板 |
| `src/lib/constants.ts` | 领域列表、免责声明、环境变量名 |
| `validateReading.ts` | AI 返回后的结构校验 |

## 8. 数据与资源

### `src/data/tarot_cards.json`

22 张大阿卡纳，每张包含：

- 中英文名称、正逆位含义
- 各 `domain` 下的领域解读
- `motifs[]`：元素 label + `bbox`（0~1 相对坐标，供 AnnotatedCard 画引线）
- `risk` / `advice`：模板引擎拼装文案用

**精调标注：** 除「高塔」外，多数 `bbox` 由脚本自动生成，位置可能不准。  
参考 `scripts/augment_motifs.py` 手调。

### `public/cards/major/`

RWS 牌面 JPG + `back.jpg`。缺失时运行：

```bash
npm run cards:download
npm run cards:wire
```

## 11. 常见问题

**Q：不接 AI 能完整演示吗？**  
能。默认 `READING_PROVIDER=template`，无需任何 Key。

**Q：模板和 AI 的 scenes 结构一样吗？**  
前端只要求 `TarotScene[]` 有 `step_label / headline / body`；AI prompt 里的 6 幕结构与模板 7 幕略有不同，接 AI 时可按产品需求统一。

**Q：如何调试 API？**  
```bash
curl -X POST http://localhost:3000/api/reading \
  -H "Content-Type: application/json" \
  -d '{"question":"测试","domain":"self"}'
```

**Q：部署要注意什么？**  
Vercel Hobby 免费够用；接 AI 时在平台环境变量里配 `LLM_API_KEY` 和 `READING_PROVIDER=ai`。
